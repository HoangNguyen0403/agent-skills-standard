## Decision Card

- **Outcome:** Operators can scan `index.html` without layout wrapping, jump between `index.html` and `report.html` sections without dead ends, and surface `ACT`/error root causes immediately to save reading time.
- **Recommendation:** Option 1 — Static-first HTML/CSS overhaul with bidirectional `index.html` ↔ `report.html` links, intra-report anchor navigation, clean table column sizing, `ACT`-vs-`WATCH` prioritization, and smart auto-expand (`<details open>`) for flagged sections, preserving strict zero-JS CSP (`default-src 'none'; style-src 'unsafe-inline'`).
  - *Strongest objection:* Without JS, operators still cannot live-filter/sort tables or click a single "Expand/Collapse all" button.
  - *Reversal condition:* If operator requires in-browser live text search, column sorting, or one-click expand-all, switch to Option 2 (CSP-hashed inline script; escalates to `tier=high` security review).
- **Scope & Non-goals:** In scope: `mcp/src/retrospective/index-report.ts`, `mcp/src/retrospective/views/report-html.ts`, cross-link context plumbing, tests, and retrospective docs. Non-goals: new data collection/session parsing rules, live LLM calls, network requests, or altering `ledger.json` schema.
- **Impact if wrong:** Fixing static layout without JS misses live multi-session filtering workflows, requiring a later CSP-scoped JS slice (low abandon cost; CSS/navigation structure stays reusable).
- **Material assumptions / Open decision:** Assumes `file://` static zero-JS security posture remains mandatory and `ags` index/report remains the primary viewing surface. Open decision: confirm Option 1 (zero-JS static) vs Option 2 (CSP-hashed JS) and proposed scope/owner.
- **Approval sought:** Approved (`requesting operator`, `2026-11-11`) for this brief and scope only (confers no implementation, spend, merge, or runtime authority).

## Problem Reframing (Explore Mode)

- **User-stated intent:** Make `ags` diagnostic UI/UX and behavior better, easier to redirect/navigate, and faster to read.
- **Underlying friction (observed in screenshot & code):**
  1. **Visual cramping & cell wrapping (`index.html`):** `.wrap` caps at `1000px` for a 10-column table without `white-space: nowrap` on date/cost/count cells or scroll wrappers, wrapping dates (`2026-\n11-11`), folder paths, branches, outcomes, and costs onto multiple lines.

  3. **Navigation dead ends:** `index.html` links one-way into `report.html` (`open`), while `report.html` has no link back to `index.html`, no links to earlier trend reports, and no intra-page table of contents / section anchors.

## Direction Options And Recommendation

### Option 1: Static-First HTML/CSS + Cross-Links + Smart Auto-Expand (Recommended)
- **What:** Improve `index-report.ts` and `report-html.ts` with clean table/card CSS, `ACT`/`WATCH` visual hierarchy, top section jump bar, bidirectional `index.html` ↔ `report.html` relative links, smart `<details open>` on flagged sections, and optional zero-JS CSS-only view toggles (e.g. `:checked` CSS filter for `ACT only`), keeping strict `default-src 'none'; style-src 'unsafe-inline'`.
- **Load-bearing assumption:** Static navigation, visual hierarchy, and auto-expanded flagged sections resolve the user's navigation and reading-speed pain without live text search or JS expand-all.
- **Evidence limits:** User's multi-session store size and current reading time are `unknown` (`measure first`); existing screenshot shows 1 session.
- **Decisive trade-off:** Preserves strict zero-script `file://` security boundary and low complexity, at the cost of no runtime keyword search or JS "Expand/Collapse all" toggle.
- **Proof:** Multi-session fixture renders cleanly in headless/local Chromium with zero mid-token wraps in numeric/date columns, working bidirectional links (`index.html` ↔ `report.html`), auto-expanded `ACT` sections, and passing CSP/no-script/XSS tests.
- **First failure condition:** User regularly inspects >20 sessions in `index.html` and needs instant keyword/folder search or single-click "Expand/Collapse all" in `report.html`.
- **Worst plausible case:** Static improvements feel insufficient for large stores, requiring a follow-up interactive JS layer.
- **Cost to abandon:** Low — layout, CSS, links, and section anchors carry over intact to Option 2.

### Option 2: Static HTML + Strict CSP-Hashed Inline Script
- **What:** Retain standalone `file://` HTML, add a deterministic inline `<script>` authorized by `script-src 'sha256-...'` (keeping `default-src 'none'`) for client-side session search, folder/ACT filtering, column sorting, and "Expand/Collapse all" buttons.
- **Load-bearing assumption:** Local browsers consistently honor `script-src 'sha256-...'` on `file://` documents and a minimal read-only script operating solely on DOM `hidden`/`open` attributes introduces no DOM-XSS sink.
- **Evidence limits:** Current test suite explicitly asserts `not.toContain("<script")` and pinned `default-src 'none'; style-src 'unsafe-inline'` (`confirmed(mcp/test/retrospective-index.spec.ts:1027)`, `confirmed(mcp/test/retrospective-report-html.spec.ts:167-174)`); cross-browser `file://` CSP-hash behavior not yet probed.
- **Decisive trade-off:** Delivers instant search/sort/expand-all without a daemon, at the cost of relaxing the zero-JS trust boundary (triggers sensitive-change risk floor → `tier=high` security review and doc/test contract updates).
- **Proof:** `sha256`-hashed inline script executes on Chromium/Safari `file://`, passes adversarial XSS fixtures, and deterministically filters/sorts rows and toggles all `<details>`.
- **First failure condition:** Target browser `file://` handling blocks CSP-hashed inline scripts or security review forbids any `<script>` alongside untrusted metadata.
- **Worst plausible case:** A DOM sink bug creates local XSS risk when viewing reports containing untrusted titles or commands.
- **Cost to abandon:** Low-medium — strip `<script>` block and restore `default-src 'none'; style-src 'unsafe-inline'`.

### Option 3: Local Loopback UI Server (`ags retrospective serve`)
- **What:** Add a loopback HTTP server (`127.0.0.1`) serving live-filtered session lists, rule drill-downs, and report views, plus optional `--open` browser launch.
- **Load-bearing assumption:** Users prefer launching a CLI server process to browse diagnostics over opening static `file://` HTML files.
- **Evidence limits:** No HTTP diagnostics viewer or port/token lifecycle exists in `mcp/src/retrospective-cli.ts` (`confirmed(mcp/src/retrospective-cli.ts:71)`).
- **Decisive trade-off:** Supports dynamic querying across large stores (>200 sessions) without file regeneration, at the cost of daemon lifecycle management, loopback security/auth hardening (`tier=high`), and breaking direct `file://` bookmarking.
- **Proof:** `ags retrospective serve` binds `127.0.0.1` with safe host/origin checks, renders filtered views, and passes integration + security tests.
- **First failure condition:** Operator expects double-clickable/bookmarkable `~/ags/diagnostics/index.html` to work without starting a server.
- **Worst plausible case:** Disproportionate engineering and security review effort for a local single-user diagnostic viewer.
- **Cost to abandon:** High — new CLI action, HTTP server, and route lifecycle to remove.

### Riskiest Assumption & Cheapest Test
- **Riskiest assumption (Usability):** Static layout fixes, bidirectional links, section jump bar, and smart auto-expand suffice without live JS search/sort/expand-all.
- **Cheapest decisive test:** Render a synthetic multi-session store (5–10 sessions with long branch/folder/title strings and mixed `ACT`/`WATCH` items) under Option 1 and inspect desktop + narrow-viewport navigation flow in a browser before deciding whether Option 2's CSP-hashed JS is needed.

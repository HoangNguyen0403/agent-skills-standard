## 1. Approved intent and BRD-lite equivalent

The maintainer uses agent-skills-standard (AGS) and OMP on two machines and wants trustworthy evidence of task effectiveness, token consumption and useful lessons. Separate usage views cannot by themselves establish which task, attempt, worker, skill version or accepted outcome generated a cost. Lower token usage is not success if quality, failed effort or analysis overhead is hidden.

## 6. Canonical product rules, flow and decisions

### Shared rules

- **Identity**: domain-scoped explicit task ID survives machine changes; run/attempt and agent/parent identity remain distinct. A collector machine is not origin identity. Copies preserve stable source-event identity. Native identifiers are mapped/pseudonymized locally, never uploaded raw. MCP process identity is not task/agent identity. Missing/ambiguous joins remain unknown; no timestamp/title/slug heuristic.
- **Evidence authority**: harness supplies usage/agent relationships/runtime versions; AGS supplies skill/version/routing/body-return observations; checks and authorized human verdicts supply outcome evidence. Discovery != body return/load != application != verification. Skill association is not whole-session cost attribution. Source-version/runtime disagreement is a coverage/compatibility issue, not permission to infer evidence.
- **Accounting**: preserve source events and provenance; deduplicate replays, apply explicit corrections as revisions, normalize cumulative versus per-request counters without adding snapshots. Cached tokens cannot be counted twice as input; reasoning cannot be added to output unless provider declares disjoint buckets. Preserve failed/retried and coordination/evaluation/reporting overhead. Measured usage and estimated money are distinct; rates require currency, rate/version and applicability. Never claim invoice savings.
- **Privacy/lifecycle**: local redaction and allowlisting precede buffering/export. Full histories stay local under their native owner. Scope authentication/authorization applies to writes and reads. Withdrawal stops new reads; deletion/expiry governs retained events, projections, buffers and replay eligibility. Exact lifecycle policy, backup handling and replay boundary require maintainer approval in SRS before activation.
- **Learning**: history is untrusted evidence, never instructions. Observation -> redacted candidate -> reproducible case -> proposed version-bound change -> paired evaluation -> independent review -> human-authorized adoption -> monitor/rollback. A rejected/inconclusive candidate is a useful disposition, not an improvement claim.

### Primary flow and recovery

The maintainer approves source/account scope and roles before enrollment. Machine operators opt in eligible local sources; collectors normalize/redact, durably buffer bounded metadata and export asynchronously at least once. One authenticated service deduplicates and derives scoped task reports. Readers inspect daily overview -> task timeline -> evidence-linked candidate; reviewers and the human maintainer gate any change. OMP Stats remains available for native inspection.

Export failures delay aggregation, not agent work. Buffer gaps, missing sources, malformed records, unavailable buckets, schema incompatibility and rejected scope are visible coverage/recovery states. Corrections change derived views with lineage, not silent event replacement. Clock order does not establish task causality. Detailed contracts, error handling and ordering belong in the [SRS](../srs/srs-agent-effectiveness-observability.md).

## 7. Goals, measurement definitions and guardrails

All numeric targets here are **proposed acceptance targets**, not observations or approved operating policy. Baseline period is **two weeks after explicit pilot authorization and readiness**, not two weeks from this document. Register report timezone, event-time window, scope, task-selection rule, cutoff and versions before collection. Late data or corrected outcomes produce a labeled report revision, not a silent denominator change.

Define **C** as distinct explicitly enrolled task IDs whose first eligible attempt starts in that fixed window and scope. Include their linked attempts through the recorded report cutoff; work continuing beyond cutoff remains open rather than silently omitted. Define **A** as tasks in C whose latest authorized acceptance verdict effective at cutoff is qualifying acceptance and has not been revoked or reopened. Report accepted, rejected/failed, abandoned, pending, reopened and unknown counts; do not restrict C to successful tasks. Abandoned tasks retain their effort in C but do not enter A. Reopened tasks retain the same task ID and all effort, leave A until renewed authorized acceptance, and are not counted as new tasks. A generic agent status cannot override the acceptance authority. Usage with no task mapping is an explicit unattributed bucket and is never allocated proportionally to A.

While the observation window or any task outcome remains open, label cohort metrics **provisional**, show unresolved counts and publish versioned snapshots. A **finalized comparison** requires a frozen cohort/cutoff, declared source coverage, disposition of every open/reopened outcome, and complete required costs for any numeric full-cost comparison. Unresolved cases keep that comparison provisional/inconclusive; never remove them to manufacture a finalized result. Later evidence or reopened acceptance creates a labeled revision, preserving the previous snapshot.

| Metric                    | Exact numerator / denominator                                                                                                                                                                                                                                   | Unknown / zero / interpretation                                                                                                                                                                                                             |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cost per accepted task    | Sum of distinct attributable effort cost across all tasks in C, including failed/retried work, divided by count(A). Include task-linked coordination and evaluation overhead once. Show unattributed and shared non-task overhead separately with scope totals. | If count(A)=0, result is undefined, not zero. If any required cost/rate is unknown, full metric is unavailable; show known subtotal plus known-cost task count/count(C), never extrapolate. Do not label a direct-only metric fully loaded. |
| Acceptance fraction       | count(A) / count(C).                                                                                                                                                                                                                                            | Empty C => no cohort, not 0% acceptance. Pending/unknown remain in denominator and are separately displayed. This is snapshot effectiveness, not pass-rate proof.                                                                           |
| Rework/attempt burden     | Distinct failed/retried attempts in C / distinct observed attempts in C, plus task-level distribution of attempt counts.                                                                                                                                        | No observed attempts => unavailable. Attempt/outcome coverage shown; absence of retries is not proven if source inventory is incomplete.                                                                                                    |
| Token consumption         | Deduplicated source-normalized token buckets for C, displayed per task and by model/provider/version; no cross-bucket grand total unless semantics support it.                                                                                                  | Missing buckets remain unknown. Cached input is a subset or disjoint only as declared by provider; reasoning inclusion follows source semantics.                                                                                            |
| Attributed usage coverage | Observed usage units with explicit task/actor mapping / all observed usage units in enrolled scope, by unit count and compatible token buckets.                                                                                                                 | Not proof of host-wide coverage. Unknown inventory means total host coverage unknown even at 100% observed attribution.                                                                                                                     |
| Source coverage           | Enrolled expected sources with valid eligible observations / explicitly declared expected sources, accompanied by missing/invalid/no-usage counts.                                                                                                              | Unknown expected inventory => unknown denominator. Zero eligible events is a valid empty state only if inventory and window are known.                                                                                                      |
| Freshness                 | Age since latest successful ingestion, plus origin observation time and buffered backlog age where known.                                                                                                                                                       | No successful ingestion => never received, not age zero. Delay must not be confused with source silence.                                                                                                                                    |
| Paired change result      | Quality and estimated-cost differences on the same prespecified task/case set between pinned baseline and proposed versions. Show matched-pair count, missing/failed cases, arm usage coverage and separately metered analysis/evaluation overhead.             | Observational associations are not causal effects. Unmatched or incomplete pairs are shown, not dropped to improve the result. No automatic machine-based treatment assignment.                                                             |
| Improvement disposition   | Count of candidates reaching accepted/rejected/inconclusive disposition with evidence/review links / candidates reviewed in the fixed baseline window.                                                                                                          | Empty review set => no dispositions, not proven learning. Adoption count and measured benefit remain separate.                                                                                                                              |

Proposed qualification target: duplicate/copy replays change totals by zero, synthetic native reconciliation has no unexplained discrepancy, approved buffer-bound recovery loses no eligible buffered events, and privacy/access tests have no unauthorized disclosure. Failed cases remain visible and block affected readiness claims. Quality guardrails: no acceptance downgrade hidden by lower cost; no unreviewed adoption; no missing failure/overhead lane; report quality regression and rollback evidence before claiming benefit. No baseline-derived savings target or statistical-confidence claim is supplied yet.

## 8. Reporting and non-functional constraints

- **Daily overview**: chosen scope/window; native measured usage versus estimated cost/currency/rate; accepted/failed/pending/unknown tasks; retries; attribution/source coverage; last ingestion and backlog; separate unattributed/analysis overhead. Scope totals cannot silently mix currencies or account domains.
- **Task timeline**: explicit task/run/agent relationships; origin versus collector; consulted skill/version/body-return evidence; check and authorized acceptance references; usage corrections with lineage; missing mapping/gap badges. Optional evidence references are opaque/redacted and access controlled.
- **Improvement queue**: redacted candidate, supporting/contrary evidence, reproducible case, baseline/change versions, eval/review/authorization/rollback references and disposition. No model-per-event processing.
- **Security**: metadata-only allowlist, domain-local pseudonymization and authenticated least-scope reads/writes are categorical invariants. Retention/deletion/replay policy approval is a prerequisite, not an implementation detail waived by a small pilot.
- **Availability/offline**: agent execution has no synchronous telemetry-service dependency. Bounded disk/outbox use, visible overflow and recovery are required. Service outage produces delayed reporting, not fabricated zeros.
- **Performance/usability**: private web reporting is the selected surface; empty/error/unknown states and status meaning must be understandable without color alone. SRS numeric resource/freshness targets must be labeled proposed, load-qualified and reviewed before implementation. No measured latency, capacity or accessibility-conformance claim exists.
- **Operational ownership**: scoped enrollment inventory, compatible adapter/runtime versions, service credentials, backup/restore/deletion procedure, backlog/coverage triage and rollback/runbook require named operations/QA/security owners before activation. No service or host is provisioned by this PRD.

# Safely rendering HTML in Angular

Prefer rendering user content as text:

```html
<p>{{ content }}</p>
```

If the application genuinely needs markup, bind it with Angular's normal HTML binding:

```html
<div [innerHTML]="htmlFromTheServer"></div>
```

Angular sanitizes strings used in an HTML context and removes or neutralizes dangerous markup such as scripts and unsafe URLs. Do not bypass that sanitizer just because content is supplied by an API, stored in a database, or generated by another user; those sources are still untrusted if an attacker can influence them.

For rich text, use a maintained sanitizer with an explicit allowlist of permitted tags, attributes, URL protocols, and resource origins. Sanitize at the trust boundary, preferably on the server as well as in the browser, and keep the sanitized value separate from the original value. Avoid direct DOM `innerHTML` assignments, custom pipes that call `bypassSecurityTrustHtml`, and string concatenation that mixes markup with user input.

Only use `bypassSecurityTrustHtml` after a narrow, reviewed trust decision for content that is genuinely controlled by the application and cannot be influenced by users or external data. Treat the result as executable authority: a mistake can create XSS. Add a strong CSP and test the rendering path with payloads containing event handlers, scripts, dangerous URLs, SVG, and malformed HTML.

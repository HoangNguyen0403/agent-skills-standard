Common iOS navigation anti-patterns to avoid:

- Overloading one screen with too many actions or destinations
- Deep, hard-to-exit navigation stacks
- Mixing navigation patterns inconsistently (tab, modal, push, drawer) without clear purpose
- Using modals for primary app flow instead of temporary tasks
- Hiding core navigation behind gestures only
- Breaking platform conventions, making back behavior surprising
- Changing tab behavior or destination unexpectedly
- Pushing users through unnecessary steps for frequent tasks
- Losing state when users go back or switch sections
- Creating ambiguous labels or icons for destinations
- Duplicating the same destination in multiple confusing ways
- Interrupting navigation with too many alerts, popups, or permission prompts
- Making navigation dependent on precise taps or small touch targets
- Ignoring accessibility, dynamic type, or VoiceOver navigation order
- Not handling deep links, handoff, or return paths cleanly

Good iOS navigation should feel predictable, shallow, consistent, and aligned with native patterns.

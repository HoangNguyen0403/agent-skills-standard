Use constructor injection by passing dependencies through initializers, define small protocols for abstractions, and keep a composition root where concrete implementations are assembled. Avoid singletons for most app logic because they hide dependencies and make testing harder. For SwiftUI, inject shared objects at the app or scene boundary and pass only what each feature needs. For UIKit, prefer initializer injection for view models, coordinators, and services, with property injection reserved for framework-owned objects when necessary. In tests, swap real implementations with mocks or fakes through the same protocol-based interfaces. Keep object lifetimes explicit, avoid service locators unless tightly constrained, and group dependency wiring in factories or containers so feature code stays focused on behavior instead of construction.

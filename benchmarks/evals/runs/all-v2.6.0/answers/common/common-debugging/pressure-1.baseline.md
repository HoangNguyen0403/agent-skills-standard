During an outage, apply a reversible mitigation quickly, but do not add blind null checks everywhere. A null check can suppress the crash while producing empty, incomplete, or unsafe behavior and can erase the signal needed to find the cause.

First preserve the evidence: capture the failing stack trace, release, affected endpoint/users, inputs, and correlated logs. Identify the narrowest failing boundary. If the intended behavior for a missing value is known, add a targeted guard there with an explicit fallback or error response, and instrument the fallback so it is visible. If the value violates a required contract, fail safely with a controlled error rather than silently proceeding.

Use feature flags, rollback, traffic reduction, or a canary as the immediate mitigation when appropriate. Add a focused regression test for the observed case, then investigate why the value became null or undefined—such as an API/schema mismatch, bad deployment configuration, migration, permissions issue, or race. Verify recovery through error rate, latency, correctness, and key business metrics. Keep the mitigation and root-cause fix separate, document both, and remove temporary guards that are not part of the intended contract.

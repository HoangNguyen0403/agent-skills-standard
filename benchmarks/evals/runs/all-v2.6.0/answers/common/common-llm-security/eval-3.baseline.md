Retrieved document chunks are untrusted external content and can contain indirect prompt injection. An attacker may place instructions in an indexed document telling the model to ignore policy, reveal context, call tools, or mislead the user. Injecting chunks into the prompt without validation also creates risks of data poisoning, cross-tenant leakage, malicious markup or delimiter confusion, and uncontrolled context or token consumption.

Treat retrieval results as data, not instructions. Put them in a clearly delimited, lower-trust context section and explicitly instruct the model to use them only as evidence for answering the user's question; never follow commands found in the documents. Prefer structured fields and a fixed template over raw concatenation. Enforce tenant and document-level authorization before retrieval, filter or redact secrets and unnecessary personal data, validate encoding and size, and cap the number and total tokens of chunks. Preserve provenance so citations and security investigations can identify the source.

Add layered defenses outside the model: content scanning and quarantine for suspicious instructions or active payloads, trusted-source and metadata allowlists, retrieval filtering by ACL, and output validation for unsupported claims, secret disclosure, and tool requests. Tool execution must require independent application authorization and, for consequential actions, confirmation. Test with poisoned documents, conflicting chunks, hidden text, encoded instructions, cross-tenant queries, prompt-boundary escapes, and oversized results. Monitor retrieval and output anomalies, and provide a process to remove or reindex compromised documents. Prompt instructions alone are not sufficient to establish trust.

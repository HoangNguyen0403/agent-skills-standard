Do not skip trigger testing. A polished description can still have poor recall, excessive false positives, or overlap with a neighboring skill. Treat the description as an activation contract and test it independently from the prose quality.

Use a small labeled suite containing clear positives, paraphrased positives, adjacent requests, and clear negatives. Check both missed activations and unwanted activations. Include the terminology users actually use, not just the skill’s preferred vocabulary. If results are poor, narrow or expand the description deliberately, add useful synonyms, state exclusions, and resolve competing skill boundaries.

Keep a regression set after each revision and report precision and recall (or equivalent counts). Only after the trigger behavior is acceptable should the description be considered finished. “Sounds good” is a subjective review; it is not evidence that routing works.

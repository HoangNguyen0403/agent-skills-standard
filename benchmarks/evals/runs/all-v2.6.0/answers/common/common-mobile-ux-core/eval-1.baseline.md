# Implementing common mobile UX core best practices

Design the experience around the user's primary task and the constraints of a small, touch-operated screen. Start by defining the key user journeys, success criteria, supported devices, and important states such as loading, empty, error, offline, permission-denied, and completed. Keep navigation predictable, preserve context when moving between screens, and make the most important action easy to find.

Use platform conventions for navigation, gestures, dialogs, typography, and system permissions unless there is a strong product reason not to. Structure screens with clear hierarchy: a concise title, meaningful grouping, readable labels, and one obvious primary action. Keep touch targets comfortably sized (at least about 44–48 dp/pt where practical), separate adjacent actions, support one-handed reach, and avoid requiring precise gestures. Respect safe areas, notches, system bars, keyboard insets, text scaling, dark mode, localization, and right-to-left layouts.

Make interaction state visible. Provide immediate pressed, focused, disabled, and progress feedback; use skeletons or stable placeholders when loading; explain failures in plain language with a recovery action; and do not discard user input. Validate near the relevant field, announce important updates to assistive technologies, provide labels and accessible names for controls, maintain sufficient color contrast, and never rely on color alone.

Optimize for real mobile conditions: intermittent networks, slow devices, battery limits, interruptions, rotation or backgrounding, and limited bandwidth. Cache safe data, make retries deliberate and idempotent, avoid blocking the whole screen for a small operation, and restore the user's state after interruptions. Test on small and large phones, different densities, reduced-motion settings, screen readers, large fonts, dark mode, poor connectivity, and both fresh and returning users. Measure task completion, error rate, latency, abandonment, accessibility defects, and crashes, then iterate from observed evidence.

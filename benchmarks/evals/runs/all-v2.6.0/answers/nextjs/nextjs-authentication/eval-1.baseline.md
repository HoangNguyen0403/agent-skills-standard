For a browser-based Next.js app, store the session/JWT in a `HttpOnly`, `Secure` cookie with an appropriate `SameSite` value and a narrow `Path`/expiration. Do not put an authentication token in `localStorage` or a normal client-readable cookie: an XSS bug could read it and exfiltrate it. A cookie is automatically sent with requests, so also design CSRF protection for state-changing operations.

Prefer a server-managed session or a short-lived access token with refresh-token rotation and revocation. Set cookies from a Server Action or Route Handler, verify the token on the server, and perform authorization checks at the data/mutation boundary—not only in middleware. Use a signing key from a server-only environment variable, validate issuer/audience/expiry, rotate keys deliberately, and clear the cookie on logout. If a client needs user state, expose a safe session summary through a server-rendered prop or authenticated endpoint, never the raw token or secret claims.

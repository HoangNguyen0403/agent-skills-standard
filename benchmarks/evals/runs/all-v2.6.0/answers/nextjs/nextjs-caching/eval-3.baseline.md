It is not safe to assume five database calls are being deduplicated. Identical `fetch` GET requests in a Server Component render can be request-memoized, but arbitrary ORM/database calls are not automatically equivalent to that fetch cache, and explicit caching behavior should be checked for the Next.js version.

Deduplicate the query at the data-access boundary. For request-scoped deduplication, wrap a read function with React's `cache` and use the same function/arguments from the components. For persistent caching, use the appropriate Next cache API (for example `unstable_cache` or the current `use cache` model) with a carefully designed key and tags. Keep personalized queries keyed by user/tenant and never persist private data in a shared cache. Measure the actual query count in development/production-like conditions, and choose `no-store` when freshness or authorization makes caching inappropriate. Passing the fetched user object down from a parent Server Component is another simple option when the tree naturally shares the same data.

First determine which layer is stale: the data source, Next Data Cache, Full Route Cache, client Router Cache, or a client library/browser cache. In Next.js 15, make the intended policy explicit rather than relying on an older default. Use `cache: 'no-store'` for request-fresh data, or set `next: { revalidate, tags }` for cacheable data.

After a successful mutation, call `revalidateTag` for tagged queries or `revalidatePath` for affected routes. If the page is already open in a client transition, use `router.refresh()` or invalidate the SWR/React Query key as appropriate; refreshing the browser alone does not fix a server cache that is still valid. Check that cache keys include user/tenant identity and that an upstream CDN/API is not serving old content. Clear/rebuild caches only as diagnosis or a deployment step, not as the permanent fix. Add an integration test that updates data and verifies the next navigation/refresh sees it, and log cache policy/invalidation events during the rollout.

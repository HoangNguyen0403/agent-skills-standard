Do not implement this as a raw red button with inline styling. Under the Flutter design-system rules, the checkout confirm action should use the project’s DLS button component first, such as `VButton`, rather than a manually styled `ElevatedButton` or `Container`. The red background must come from a semantic color token like `VColors.critical`, `AppColors.error`, or the equivalent destructive/critical button token defined by the system, not from `Colors.red` or `Color(0xFF...)`. The white label color should likewise come from the matching on-color token, not a hardcoded value.

Typography should also stay inside the system. If the app is theme-driven, the button label should use the appropriate button or body style from `Theme.of(context).textTheme` and let the theme own the font sizing. If the design system explicitly maps that role to a 16px button label, that sizing belongs in the theme or token layer rather than an inline `TextStyle(fontSize: 16)`. The correct outcome is: a confirm button built from the DLS component, using semantic destructive-or-primary button tokens, with text styling resolved through theme or typography tokens so states like pressed, disabled, and dark mode remain consistent.

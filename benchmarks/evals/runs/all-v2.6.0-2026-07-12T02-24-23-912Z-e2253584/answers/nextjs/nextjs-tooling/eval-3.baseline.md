Classify variables by where they may be exposed. Keep secrets such as database URLs, signing keys, API private keys, and passwords in server-only variables without `NEXT_PUBLIC_`; read them only in Server Components, Route Handlers, Server Actions, or server modules. Variables prefixed `NEXT_PUBLIC_` are bundled into browser JavaScript and must be treated as public. Values passed as props or returned by an endpoint are also public regardless of their original name.

Use `.env.local` for local secrets and never commit it; commit only a documented `.env.example` with placeholders. In CI/deployment, inject values through the secret manager, validate required variables at startup, and keep dev/test/prod configuration explicit. Remember that public variables are often inlined at build time, so changing them may require a rebuild; server runtime variables can be supplied at container start depending on deployment. Avoid logging `process.env`, source-map exposure, and accidental imports of server config into Client Components. Rotate a secret immediately if it reaches a client bundle or repository.

Do not treat a direct 12-to-15 jump as automatically faster. It may be technically possible, but it combines multiple major-version changes and makes failures harder to attribute. Take a clean baseline and upgrade through the relevant migration steps (13, 14, then 15), applying official codemods and reading each version's breaking-change notes even if you update dependencies in one branch.

Run typecheck, lint, unit/E2E tests, and production builds after each meaningful step. Audit the Pages Router data APIs, any App Router adoption, async request APIs in Next 15, React compatibility, caching/revalidation behavior, middleware/runtime, image/font/config changes, and custom webpack/plugins. Keep commits separated by major-version migration so a regression can be bisected. If the project is small and tests are strong, a single dependency update can be a reasonable experiment, but keep the intermediate migration checklist and rollback available. Measure the total engineering and verification time, not just the number of package-install commands saved.

# Secure email/password authentication

Treat registration, login, password reset, session refresh, and logout as trust boundaries. Validate and normalize email input at each API boundary, enforce a documented maximum length, and reject malformed or unexpected fields. Do not log email addresses, passwords, reset tokens, session tokens, or other PII; mask or omit sensitive values.

Store only a normalized email and a password hash. Never store or transmit plaintext passwords and never hardcode signing keys, encryption keys, database credentials, or default passwords. Generate secrets from environment variables or a managed secret store, with rotation procedures. Hash passwords with a password-specific adaptive KDF such as Argon2id (or a comparably configured password-hashing library), using a unique random salt and parameters that are periodically reviewed. Password reset tokens must be high-entropy, single-use, short-lived, stored hashed, and invalidated after use.

Use MFA where practical, especially for administrative or high-risk actions. Apply rate limits and progressive backoff to login, registration, reset, and verification endpoints; avoid account-enumeration leaks by returning equivalent generic responses for unknown emails and invalid credentials. Compare credentials through the password-hashing library and use generic authentication failures rather than exposing stack traces or internal details.

After authentication, issue a securely generated, opaque session identifier in a cookie configured with `Secure`, `HttpOnly`, and an appropriate `SameSite` policy. Rotate the session identifier after login and privilege changes, expire idle and absolute sessions, revoke them on logout or suspected compromise, and protect state-changing browser requests against CSRF. If using JWTs instead, validate signature, issuer, audience, expiry, and algorithm at every entry point; keep access tokens short-lived and use securely rotated refresh tokens. Authorize every protected operation server-side with least privilege—authentication is not authorization.

Encrypt sensitive data in transit with TLS 1.3 and use encryption at rest (AES-256 where application-level encryption is required). Minimize collected data and maintain audit logs for authentication, password reset, MFA, session revocation, and administrative changes without recording secrets or unmasked PII. Run dependency scanning, SAST, and DAST in CI before merge, and test abuse cases such as brute force, replay, fixation, CSRF, reset-token reuse, and privilege escalation.

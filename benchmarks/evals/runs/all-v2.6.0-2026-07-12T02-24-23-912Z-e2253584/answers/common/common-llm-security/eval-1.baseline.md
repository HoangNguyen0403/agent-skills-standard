This is a prompt-injection risk caused by treating untrusted user content as part of the system instruction. A user can insert text such as “ignore previous instructions” or attempt to redefine the assistant's role, priorities, tools, or output constraints. Because the application concatenates the message into the system prompt, the model has no reliable structural distinction between trusted policy and attacker-controlled data.

The fix is to keep the system/developer instructions in a separate, immutable message or template and pass the user message as a distinct user message or bounded variable. Do not interpolate raw user text into privileged instructions. Apply input-size and encoding controls, and clearly delimit any user text that must be quoted. Treat model output as untrusted too: validate it against an allowlisted schema, enforce authorization in application code, and never let the model grant itself permissions or directly execute sensitive actions.

Add adversarial tests for instruction override, role confusion, delimiter escape, prompt leakage, tool-selection manipulation, and oversized or encoded payloads. Log the relevant prompt version and security events without storing unnecessary sensitive content. If the chatbot has tools or handles sensitive data, enforce least privilege, authorization, and output/data-loss filtering outside the model. Prompt wording can reduce risk, but it is not a security boundary; trusted policy and access control must be implemented in code.

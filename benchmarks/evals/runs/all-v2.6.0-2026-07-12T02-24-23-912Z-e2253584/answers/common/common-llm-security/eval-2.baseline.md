This design creates a high-impact excessive-agency risk. An autonomous agent that can read and delete files can be induced, through a malicious prompt, compromised retrieved content, or an ordinary misunderstanding, to destroy data or disclose sensitive files. The absence of confirmation removes an important control for an irreversible operation.

Separate planning from execution and require explicit, human-approved confirmation for destructive, high-impact, or broad-scope actions. The agent should first produce a proposed operation with the exact paths, reason, affected files, and estimated impact; the application—not the model—should enforce the approval gate. Use least-privilege credentials, restrict access to an approved workspace, deny traversal and symlink escapes, canonicalize paths, and apply an allowlist rather than relying on model instructions. Prefer reversible operations such as quarantine or a versioned trash area, with backups and a tested recovery path.

Also constrain bulk operations with scope, count, and rate limits; require revalidation immediately before execution to avoid time-of-check/time-of-use changes; and record an audit trail of requester, approval, model/tool call, paths, result, and failure. Add tests for path traversal, symlinks, hidden/system files, wildcard expansion, prompt injection, stale approvals, concurrent changes, and partial failure. Reads should be filtered for secrets and authorized per user. If an emergency automation mode is necessary, make it narrowly scoped, time-limited, separately authorized, and monitored rather than generally autonomous.

# Website Analytics Contract & Operations Runbook

## Status and authority

Website analytics is **disabled by default**. In accordance with SRS-009, PRD REQ-017, and the approved Plausible collection contract (`docs/product/evidence-led-marketing/plausible-collection-contract.md`), no telemetry script, collector, SDK, or network request is emitted in unconfigured, local, preview, or default builds.

Enabling collection requires an explicit human operator approval gate and valid non-secret configuration. A build flag alone is **not** authorization to collect data.

## Architecture: Direct Events API

The website implements a direct browser POST integration with Plausible Analytics (`POST https://plausible.io/api/event`):

- **No tracker SDK**: No external script tag (`<script src=".../plausible.js">`) is ever injected.
- **No automatic pageviews**: Pageviews are not tracked; only 4 explicit user-initiated application actions are instrumented.
- **No global click listeners**: No broad document event listeners or link interceptors.
- **No cookies or visitor IDs**: No tracking cookies, local storage tracking IDs, or persistent fingerprints are generated or retained.
- **No backend or proxy**: Direct browser POST with failure isolation.
- **Preserved static export**: Static Next.js export (`output: 'export'`), server pre-rendering, accessible captions, and no-JavaScript navigation remain fully functional. Without JavaScript the demo keeps its native video controls.

## Demo video entry: approved explicit first start

Collection builds use an explicit, accessible entry for the demo video so that only a genuine user activation can begin counted playback. This is an approved UX contract, not an analytics side effect:

- **Default/unconfigured builds**: the existing native `<video controls>` player is unchanged and no analytics entry control is rendered, because no collection exists.
- **Configured collection builds**: after client hydration an accessible **Play demo (56s)** button is the only entry that may produce `demo_play`. Its trusted click/keyboard activation is the only caller of `video.play()`. The entry is rendered whenever collection is configured, independent of the current consent state: declining or starting before opt-in still plays the media, it just emits nothing.
- **Native controls remain the fallback**: native controls are hidden only until the first successful decoded playback (`playing`), then revealed for the rest of the page lifecycle. Pause, resume, seek, captions, volume, and keyboard control are never intercepted, and resume is never counted. Playback that began through the server-rendered native controls before hydration is adopted as already started, without reloading media and without attribution.
- **No-JS/SSR**: the server-rendered player keeps native controls and renders no inert button; the explicit entry requires hydration. Native playback without JavaScript remains usable and emits no analytics events.
- **Failed start**: a rejected or failed `playing` attempt is reported with an accessible retry button and emits nothing. Primary media path is never blocked.
- **Consent binding**: the consent snapshot is captured at the explicit start activation. Starting before opt-in plays the media and emits nothing; later opt-in never replays that start, and withdrawing or re-granting while the start is pending invalidates the pending epoch.
- **Programmatic play**: `video.play()` invoked without the explicit trusted activation emits nothing.

## Configuration & operator approval gate

For collection to become active, all of the following build-time inputs must be explicitly set and validated:

| Environment variable | Purpose | Validation rules |
| --- | --- | --- |
| `NEXT_PUBLIC_PLAUSIBLE_ENABLED` | Feature switch | Must be explicitly `"true"`. |
| `NEXT_PUBLIC_PLAUSIBLE_OPERATOR_APPROVAL` | Operator approval gate | Must be explicitly `"approved"`. Documented human signoff is required. |
| `NEXT_PUBLIC_PLAUSIBLE_SITE_ID` | Site domain identifier | Non-empty alphanumeric/domain string (e.g. `agent-skills-standard.org`). |
| `NEXT_PUBLIC_PLAUSIBLE_PAGE_URL` | Fixed constant HTTPS URL | Absolute HTTPS origin/path (e.g. `https://agent-skills-standard.org/`). Must **never** be dynamic `location.href`, query string, or hash. |

If **any** of these inputs is missing, invalid, or unapproved:
1. `isPlausibleConfigured()` returns `false`.
2. The consent prompt is not rendered in default builds, preventing unnecessary UI intrusion.
3. All event dispatch functions immediately return with zero network activity.
4. CSP headers generated by `scripts/generate-headers.mjs` retain strict `connect-src 'self'`.

## Consent, privacy notice, and withdrawal

1. **Explicit opt-in**: Collection is dormant until the visitor explicitly clicks "Accept analytics".
2. **In-memory only consent**: Consent state (`granted` or `denied`) is held strictly in in-memory React state and ref, defaulting to `undecided` on every page load. Strictly zero `sessionStorage`, `localStorage`, or cookies are written or read.
3. **Immediate withdrawal**: Visitors can withdraw consent at any time. Withdrawal immediately stops all future network transmissions and invalidates in-flight action tokens.
4. **No pre-consent buffering**: Events triggered prior to explicit opt-in are **never** buffered, queued, or replayed upon consent.
5. **Truthful privacy notice**: The consent interface discloses that Plausible processes browser IP and User-Agent into a daily rotating visitor hash (salt deleted every 24 hours), and that individual event and session records are stored (not aggregate-only storage) with up to 5-year retention under Plausible Business terms. The notice explicitly avoids misleading "completely anonymous" or "no identifiers" claims, acknowledging that browser IP, User-Agent, and Origin are disclosed during network transmission, and links to vendor privacy documentation.
## Allowed events and closed application fields

Only four application events are defined and permitted:

| Event name | Trigger condition | Placement allowlist |
| --- | --- | --- |
| `demo_play` | Explicit **Play demo** entry activation followed by actual successful decoded playback (`playing`); once per media instance / page lifecycle. Never on render, failed start, programmatic `video.play()`, or pause-resume through native controls. | `quickstart_demo` |
| `install_command_copy` | Actual resolved, non-stale clipboard write success. Never on clipboard rejection or manual-recovery fallback. Clipboard contents are never collected. | `quickstart_init`, `quickstart_sync` |
| `setup_guide_open` | Explicit user click on a setup documentation or tutorial link. | `quickstart_docs`, `quickstart_tutorial` |
| `github_click` | Explicit user click on a primary GitHub repository link. | `header_github`, `community_github`, `footer_github` |

### Closed payload schema

Every outgoing event payload contains strictly bounded fields:

```json
{
  "name": "<event_name>",
  "domain": "<approved_site_id>",
  "url": "<constant_approved_https_url>",
  "props": {
    "schema_version": 1,
    "campaign_id": "<registered_campaign_or_unknown>",
    "asset_id": "<associated_registered_asset_or_unknown>",
    "placement": "<allowlisted_placement_or_unknown>"
  }
}
```

- **Validation**:
  - `campaign_id` must be registered (e.g. `standards-demo-01`); otherwise normalized to `"unknown"`.
  - `asset_id` must be registered in authoritative campaign frontmatter (`tutorial-standards-adoption-01`, `announcement-github-01`, `showcase-community-01`); unregistered demo and copy actions normalize to `"unknown"`.
  - `placement` must be in the allowlist; otherwise normalized to `"unknown"`.
  - Arbitrary URL query parameters, referrers, user IDs, or code snippets are strictly excluded.

## Content Security Policy (CSP)

`website/scripts/generate-headers.mjs` shares the exact canonical predicate `validatePlausibleConfig`:
- **Default build**: `connect-src 'self'`.
- **Approved collection build**: `connect-src 'self' https://plausible.io/api/event`.
Only the exact collection endpoint path is allowlisted; no host wildcards or generic origin parameters.
## Transport failure isolation

Network or transport failures (e.g. ad-blocker blocking, offline status, or Plausible endpoint downtime) are caught silently. Telemetry errors **never** interrupt video playback, clipboard actions, navigation, or accessible recovery.
